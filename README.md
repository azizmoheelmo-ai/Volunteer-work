# تقرير فرصة تطوعية مدرسية

تطبيق ويب (PWA) بملف واحد `index.html` لإنشاء تقارير الفرص التطوعية المدرسية وشهادات الشكر والتقدير، وفق بنك الفرص التطوعية المدرسية (وزارة التعليم). يعمل بلا خادم ويُنشر على Vercel.

## الميزات
- **النموذج العادي:** اختيار الفرصة، تعبئة بياناتها تلقائياً (قابلة للتعديل)، ثم «إنشاء التقرير» وطباعته أو حفظه PDF.
- **الجولة التفاعلية** (زر «＋ جولة تفاعلية» أسفل اليسار): معالج بلاطة لكل سؤال، يستخدم نفس حقول النموذج.
  - **إنشاء تقرير خطوة بخطوة.**
  - **شهادة شكر وتقدير** (طالب / طالبة):
    - الفرصة الجاهزة تملأ الساعات تلقائياً، و«أخرى» تُكتب يدوياً.
    - الاتجاه يختاره المستخدم: **أفقي** أو **رأسي** (A4)، والمعاينة تتبع الاختيار.

## متابعة ساعات الطلاب (المرحلة الأولى — تجريبية)
قاعدة بيانات على جهاز المعلم (IndexedDB)، بلا خادم ولا حساب. الملف: `tracker.js`. تُفتح من قائمة الزائد ← «ساعات الطلاب».
- **القاعدة:** 100% = 40 ساعة (قابلة للتعديل في «حفظ البيانات»)، أي 2.5% للساعة، والتراكم على ثلاث سنوات، وقد تتجاوز النسبة 100%. المرحلة الثانوية فقط (أول/ثاني/ثالث).
- **الطلاب (بلاطتان):** «إضافة يدوي» و«استيراد»، كل منهما بخطوات: الصف ← الفصل (موجود أو جديد) ← الاسم أو ملف الأسماء. بعد كل إضافة يبقى المعلم في نفس الفصل لطالب آخر. الاستيراد لفصل واحد (Excel أو CSV أو لصق)، ومنه رابط «الملف فيه أكثر من فصل أو صف؟» لاختيار الأعمدة. و«عرض الطلاب وتعديلهم» للبحث والتعديل والحذف.
- **تسجيل الساعات من ملف المنصة** (أعمدة `VolunteerName, UnifiedVolunteerId, Shift, NumberOfVolunteeringHoursDuringShift`): يحدد المعلم الفرصة والتاريخ وعدد الأيام والفترة. الساعات = ساعات الفترة × الأيام. **رقم الهوية يُتجاهل ولا يُحفظ**، ولا يُحفظ الملف.
- **المطابقة بالاسم** بعد توحيد الكتابة (الهمزات، ة/ه، ى/ي، «بن»، الالتصاق). المطابق تماماً يُسجَّل تلقائياً، وغيره يراجعه المعلم: اختيار من المقترحات أو تجاهل أو إضافته طالباً جديداً. لا يُقبل اقتراح تلقائياً.
- **تسجيل يدوي:** تحديد الطلاب بفلتر الصف والفصل وساعات اليوم × الأيام.
- **الأمان:** كل رفع دفعة تُحذَّر عند تكرار (فرصة+تاريخ+فترة) وتُحذف بنقرة؛ نسخة احتياطية JSON واستعادة؛ طلب تخزين دائم من المتصفح؛ تنبيه لتثبيت التطبيق.
- **قراءة Excel** داخل التطبيق بلا مكتبة (ZIP + `DecompressionStream`)، ويقبل أسماء العناصر ببادئة (`x:row`). صيغة xls القديمة غير مدعومة (يُطلب حفظها xlsx).
- يغذّي اختيار الطالب في شهادة الشكر وطباعة شهادات شعبة كاملة.
- لاحقاً: تقارير الشعبة والتحليل وربط الشهادات بمن أكمل ساعاته.

## الشهادة: Chrome وسفاري يطبعان بشكل مختلف
قِيس السلوك من ملفات PDF حقيقية أرسلها المستخدم (Chrome على أندرويد وسفاري على iOS 26):

| | Chrome | سفاري (iOS) |
|---|---|---|
| اتجاه الصفحة | يطيع `@page { size }` | يطيعه في ملفاتنا، ويعرض الاتجاه أيضاً في نافذة الطباعة |
| الهوامش | يطيع `@page { margin: 0 }` | يتجاهلها ويضع هوامشه (جانبية ~21–32pt، علوية ~65pt في الأفقي) |
| تحجيم المحتوى | لا يغيّره | **يكبّر/يصغّر المحتوى ليملأ عرض منطقة الطباعة** (أفقي ≈ 798×452pt) |
| ترويسة وتذييل | لا يضيف | يضيف الرابط والتاريخ ورقم الصفحة |

لذلك لكل متصفح تخطيطه (الدالة `certCfg` في `index.html`):
- **Chrome أفقي:** الشهادة 1123×794 تملأ صفحة A4 كاملة (هامش 0). **Chrome رأسي:** 604×900 مكبّرة 1.12.
- **سفاري أفقي:** الشهادة 1123×**610** (نسبة أعرض من A4)، لأن سفاري يملأ العرض فيصبح الارتفاع المطبوع ≈ 433pt ويتسع في الـ452pt المتاحة. التخطيط الأصلي 1123×794 كان ينزل إلى صفحة ثانية.
- **سفاري رأسي:** 604×900 (كان يعمل جيداً).
- الاكتشاف: آيفون/آيباد/ماك أو Safari (وChrome على iOS لأنه نفس المحرك).

أخطاء أُصلحت على الطريق:
1. **طباعة التقرير بدل الشهادة:** كانت نسخة الطباعة تُزال بعد 1.5 ثانية، وسفاري يعيد رسم الصفحة عند تغيير خيارات الطباعة. الآن تبقى طوال خطوة المعاينة وتُزال عند الخروج.
2. **صفحة فارغة ثانية في Chrome الرأسي:** `min-height: 100vh` في `body` يتجاوز الصفحة مع أي هامش. أُلغي وقت طباعة الشهادة.
3. **الأفقي صغير في Chrome:** كان يُطبع بهوامش سفاري، وصار يملأ الصفحة.

التحقق (Chrome، محاكاة وكيل المستخدم لكل متصفح، طباعة PDF): الأفقي والرأسي صفحة A4 واحدة بالاتجاه الصحيح في الحالتين، والتقرير ما زال صفحتين. أرقام سفاري محسوبة من قياسات ملفاته، ولم تُجرَّب على جهاز.

## مشكلة معروفة: طباعة التقرير على آيفون
نسبة «التحجيم» التي يختارها سفاري تلقائياً تتغير أحياناً (86% أو 91%)، وعند 91% قد ينقسم التقرير إلى 4 صفحات بدل 2. لم نصل بعد إلى السبب المؤكد. قيد المتابعة بعد تجربة المستخدم.

## هيكل المشروع
- `index.html`: الصفحة والأنماط والمنطق (التقرير، المعالج، الشهادة).
- `sw.js`: Service Worker (يُرفع رقم `CACHE` مع كل تحديث ليصل التغيير للمستخدمين).
- `fonts/`: خط هوية الوزارة. `icons/`: الأيقونات وشعار الوزارة.
- `api/`، `vercel.json`: إعدادات النشر.
